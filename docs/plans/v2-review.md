1. Dark-theme mood tints collide (ui/month/MonthSections.kt:56-66). In the dark scheme primaryContainer and tertiaryContainer are both #8E5A5F (Theme.kt:87,95), so mood 5 (very happy) and mood 2 (sad) look the same. Mood 3 uses surfaceContainerHighest, which is close to the card colour, so neutral days look untinted (the screenshot reviewer confirmed this on month_dark_*). Fix: give each of the 5 moods its own container and on-colour pair, distinct in both themes; keep the HARD rule (each number drawn in its tint's on-colour). Make the month sample cover moods 1-5 and re-record.
2. Edits made before load() finishes are lost (ui/common/Autosaver.kt:26,43; WeekViewModel.kt:67; MonthViewModel.kt:75). While `ready` is false, flush() returns but leaves the keys dirty, and setting `ready = true` never starts a new flush. Also load() overwrites goals/todo/notes/review with the DB values, so text typed during load is replaced. Fix: have the ready setter flush pending keys, and ignore edits until loaded (or merge them); apply to both VMs.
3. Autosaver.scope (Autosaver.kt:22) is never cancelled, so each Week/Month VM leaks a scope. Fix: after the final flushNow() from onCleared, cancel the scope once that write has finished.
4. Hard-coded user-facing text: WeekSections.kt:154 `Text("-")` for a missing mood. Fix: use a strings.xml resource (e.g. reuse habit_summary_none or add mood_missing_short).
